## 不能混同的三条轨

| 轨道 | 来源/入口 | 可以得出的结论 |
|---|---|---|
| 历史固定预算适配 | exp008/009及exp016_local_baselines，exp/train/train_baselines.py | 特定LoRA/114步配置的表现，不是原论文最佳结果 |
| 冻结上游损失重实现 | exp015_complete_baselines、exp016_8b_multiseed；reproduction_losses.py及reproduce_all_baselines.py | 明示YAML、语义修正、原生/LoRA和执行适配；公式通过不代表端到端作者复现 |
| 独立来源对齐实现 | baselines/recipes.py、objectives、protocol及来源锁 | 配方、提示、早停及搜索独立维护；不得不经审核与旧轨并表 |

同模型、同LoRA和相同步数只能控制部分变量。额外F1指导、16锚点、反馈和评分都增加信息/计算；RMU受限层与全text LoRA不是同参数范围。跨轨不能共用一列“heldout”或直接作总排名。

## 各方法的实质差异

| 方法 | 正确比较前必须核对 |
|---|---|
| GA | 负answer CE；无保护容易广泛退化。固定114步与达到同UA后的比较分开 |
| GradDiff/GA-ret | 遗忘/保持权重；旧配置1/1，FaithUn说明为.7/1。保持NLL与KL不是同一方法配置 |
| NPO | 使用序列总NLL和冻结参考；构造默认beta1、上游YAML .1与论文搜索范围不能混称同配方 |
| SimNPO | 长度归一化、beta和遗忘系数共同决定强度。旧YAML4.5/.125与独立baselines作者来源配方不同；不得因单点饱和判算法无效 |
| RMU | steering、保持权重、层hook、原生矩阵/LoRA范围。历史down_proj5–7/steer20与上游全text适配/steer2不同；FaithUn还搜索保持权重 |
| DPOmis/rej | 冻结参考、forget替代答案、retain偏好目标与拒答原文。旧retain NLL和固定“I don't know.”不等于FaithUn配方，改写问题也不等于失配答案 |
| CEU | detach目标、正确标签抑制及首答案token规则；不额外加retain。旧本地F0中4/33单token答案被跳过，需报告有效样本/update，不偷偷换公式 |
| PDU | logit spread、epsilon约束、对偶更新和预热。114步不足5轮时标no-dual，不当完整PDU；epsilon不能默认未知值为论文值 |
| WGA/SatImp | detach置信度权重、系数与梯度量级；类默认、YAML、作者说明有差异，保留具体来源而非统一称“官方默认” |
| UNDIAL | 冻结teacher、惩罚强度、token范围、学习率；旧YAML与独立配方不同。忽略标签修复改变了上游有问题的实现，不是逐位相同 |
| KLUE | 原生归因/筛样/掩码合同见下节，不能以LoRA近似补一个同名分数 |

已发现的语义修正必须随配置公开：RMU在batch>1避免归一化广播成B×B，batch1不变；UNDIAL排除-100标签及提示位置的目标索引/CE。保留上游原样作为审计参照，不能把“执行上游代码”自动当成算法正确。

## KLUE专项合同

来源：FaithUn论文EMNLP2025主会657、arXiv2502.19207v2，Section4和AppendixB.3。2026-10-22/23公开yny0506/faithun仓库审查只见数据/split/README/LICENSE，未见可执行训练归因代码；不推断作者永远没有其他实现。KLUE与CLUE不是名称变体。

1. 对完整答案概率做activation×gradient，token维max；不能暗换平均logprob并称完全一致。
2. 保留答案，从训练forget/retain采5个失配问题；失配正归因截零后以alpha10扣除，排除规则/随机流固定。
3. 每轮筛选仍满足记忆判据的样本，batch4、最多150epochs，训练UA≤.33早停；论文低可达学习率搜索与单点lr1e-5不同。
4. 全局top5%神经元。gated-MLP约定为pre-down激活、gate/up行和down列，聚合/tie规则与掩码时机显式固定；不是作者已公开代码认证。
5. 原生掩码Adam、CPU FP32主副本/动量、未选权重和历史动量抑制及保存恢复都要实测。BF16反向可能下溢，double概率标量不保证全链FP64；全零/非有限门不替代精度敏感性对照。

代码流程存在、toy通过、smoke通过、正式完成、作者级复现是不同阶段。已知8B注意力后向对齐错误只说明执行失败，不能填0、推断KLUE效果差或自动改成LoRA。

## 四个核心验收问题

| 风险 | 验收要求 |
|---|---|
| 提示/评分不同 | 同一checkpoint交叉评测原文MCQA模板、仅答案条件概率和历史全串均值；固定选项顺序及tie处理。全串评分受公共题干和长度影响，风险不等于排名已证反转 |
| 预算/终点不同 | 固定预算与统一UA终点分轨；训练/早停/调参/测试权限写清，各方法有等额开发集搜索。不看测试多跳成绩挑赢家 |
| 数据访问不同 | C1/C2披露F1访问；原生轨用retain66时后33不是heldout；独立保持用未训练test，图相关性分层另冻结 |
| 更新/资源差异 | 对齐初始化、forget/retain/alternate独立随机流、答案掩码、归约、裁剪、LR日程、精度和优化器；CPU流式/offload显式标记，OOM不静默改方法 |

每方法先源公式及独立梯度测试，再真实模型前向/反向/一步更新/保存恢复门检；PDU须对偶实际激活，CEU列跳过，KLUE列归因与掩码检查。多seed重复固定坏配方不是充分调参；未测MMLU/PPL不拿retain代替。

报告必须列原生/适配、超参数来源、模块与参数量、有效update、调参预算、原始题目/逐题分数、成本和失败原因。当前[独立baseline说明](../../baselines/README.md)负责可执行配方，[主表](../../exp/analysis/cloud_comparison_20261022/README.md)负责结果；本文件只维护审计门，不复制历史分数表或逐轮进度。
